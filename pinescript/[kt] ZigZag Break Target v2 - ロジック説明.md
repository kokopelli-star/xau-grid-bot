# [kt] ZigZag Break Target v2 — ロジック説明

対象ファイル

- `[kt] ZigZag Break Target v2.pine` — 本体（indicator版、アラート送信）
- `[kt] ZigZag Break Target v2 Strategy.pine` — 同一ロジックの strategy版（バックテスト用）

---

## 1. 何を狙う戦略か

一言でいうと **「勢いよく伸びた波の“行き過ぎ”を逆張りする」** ロジックです。

ZigZagで直近の1波（安値→高値、または高値→安値）を測り、その波が

1. 適度に押し／戻しを入れてから（38–62%）
2. 元の方向へ**ブレイク**した

とき、「このブレイクは波幅の138–162%まで伸びたら息切れする」と仮定して、**その到達予想ゾーンで反対方向に仕掛ける**。上昇ブレイクなら上のゾーンで **売り**、下降ブレイクなら下のゾーンで **買い** です。これが `waveDir` と `tradeDir` が逆になる理由です。

```
                                 ┌────────────┐ 162%  3327.2
                                 │ TARGET ZONE│  ← ここで SELL
                                 └────────────┘ 138%  3312.8
        H 3290 ●───────────── break (close > 3290)
             /│\      /
            / │ \    /        ← ①押し目 38-62% (3252.8〜3267.2) で arm
           /  │  ●__/         ← ②高値ブレイクで arm 解除 → ゾーン生成
          /   │
         /    │ range = 60
   L 3230 ●───┘
```

## 2. 処理の流れ（5段階の状態遷移）

```
IDLE ──(押し38-62%)──> ARMED ──(ブレイク)──> ZONE ──(到達)──> ENTRY
  ▲                      │                    │
  └──(起点割れ/N本/切下高値)┘                    └──(期限切れ/SL先着/TP方向へ逃げ)──> CANCEL
```

### 段階1: ZigZagで波を作る

`ta.pivothigh/pivotlow(depth, depth)` で、左右 `depth` 本より高い高値／安い安値をピボットとして検出。高値と安値が**必ず交互に並ぶ**よう管理し（高値が連続したら高い方で上書き）、直近2点 `prev`→`cur` を「現在の波」とします。

> ピボットは性質上 `depth` 本遅れて確定します（depth=8なら8本後）。これはZigZag共通の宿命で、リペイントではありません。

### 段階2: 押し目／戻りを待つ（ARM）

上昇波なら `r = (波の高値 - 終値) / 波幅` を毎確定足で計算し、`r` が 0.38〜0.62 に入った瞬間にアーム。このとき **baseHigh / baseLow / 方向を凍結**します（以降、新しいピボットが出ても凍結値は動かない）。

### 段階3: ブレイク or キャンセル

アーム中、確定足の終値が

- `close > baseHigh`（上昇波）→ **ブレイク成立**
- そうでなければ3つの失効条件をチェック
  - `full_retrace` — 100%戻した（起点割れ）＝波そのものが否定された
  - `timeout` — 60本待っても動かない
  - `lower_high` — baseHighを超えられない高値ピボットが確定（＝ブレイク失敗の構造）

### 段階4: ターゲットゾーン生成

ブレイク足で、起点（baseLow）から測った拡張レベルを計算します。上の図の数値だと:

| 項目 | 計算 | 値 |
|---|---|---|
| ゾーン手前 138% | 3230 + 60×1.38 | 3312.8 |
| ゾーン奥 162% | 3230 + 60×1.62 | 3327.2 |
| SL 190% | 3230 + 60×1.90 | 3344.0 |
| TP 100%（ブレイク起点） | 3230 + 60×1.00 | 3290.0 |

ここでフィルタ（上位足トレンド／ATR／時間帯／最小RR）を通し、通ったものだけをbotに送ります。

### 段階5: エントリー判定

- `touch` — 指値価格に触れた瞬間に発注
- `confirm` — ゾーン内で反転足（上ヒゲピンバー or 陰の包み足）が**確定**してから成行

ゾーンの破棄条件は3つ。いずれも `cancel` イベントを送ります。

| reason | 条件 |
|---|---|
| `expired` | 到達しないまま `zoneValidBars`（既定30本）経過 |
| `sl_before_entry` | ゾーンを突き抜けてSL水準に先着 |
| `stale` | ブレイクを打ち消す深い戻し（既定: 波の61.8%地点まで戻る） |

`stale` の水準はブレイク水準（100%）ではなく `staleLevel`（既定 0.618）で指定します。上の数値例なら `3230 + 60×0.618 = 3267.1` を下回ったら破棄。ブレイク直後の押し戻し（3290付近への戻り）では破棄されません。

## 3. 注意すべき設計上のトレードオフ

### RRが `entryEdge` で大きく変わる

上の数値例だと:

| entryEdge | エントリー | TPまで | SLまで | RR |
|---|---|---|---|---|
| near (138%) | 3312.8 | 22.8 | 31.2 | **0.73** |
| mid (150%) | 3320.0 | 30.0 | 24.0 | 1.25 |
| far (162%) | 3327.2 | 37.2 | 16.8 | **2.21** |

`near` は約定しやすい代わりにRRが1を切ります（勝率73%以上必要）。`far` はRR2.2ですが、そこまで伸びずに反転すると取り逃がします。**どちらが優れているかはバックテストでしか分かりません** — strategy版で `entryEdge` を3通り回して比較するのが最初にやるべきことです。`minRR` を設定すればRR不足のゾーンを自動で捨てられます。

### 逆張りの本質的リスクは消えていない

138–162%は目安にすぎず、強トレンドでは261.8%まで平気で伸びます。`htfMode=align`（上位足EMAと同方向の発注のみ許可＝トレンドに逆らう逆張りを排除）はそのための最低限の保険ですが、有効かどうかも検証が必要です。

## 4. アラートJSON（Any alert() function call）

```json
{"ver":"2.0","event":"zone","id":"12","symbol":"XAUUSD","tf":"15","time":1754006400000,
 "wave_dir":"up","trade_dir":"sell","entry_mode":"touch",
 "zone_min":3312.45,"zone_max":3325.10,"entry":3312.45,"sl":3334.20,"tp":3290.00,"stale":3267.08,"rr":1.03,
 "base_high":3290.00,"base_low":3230.00,"range":60.00,"atr":4.21,"htf_trend":-1,
 "valid_bars":30,"valid_until":1754033400000}
```

`event` は4種。`id` で同一ゾーンを紐付けられます。

| event | 意味 |
|---|---|
| `zone` | ゾーン生成。botは指値の準備をする |
| `entry` | 発注トリガ（touch: 指値到達 / confirm: 反転足確定） |
| `cancel` | 失効。`reason` = `expired` / `sl_before_entry` / `stale` / `superseded` |
| `zone_filtered` | フィルタで除外されたゾーン（**発注対象外**）。`alertFiltered` を ON にしたときだけ飛ぶ |

`zone_filtered` は「フィルタが何をどれだけ弾いているか」を記録するための通知専用イベントです。ゾーン状態を一切更新しないため `id` は常に `null`、`entry_mode` / `stale` / `valid_*` も持ちません。`reason` は `passed` の評価順に沿った最初の不成立要因（`trend` / `atr` / `session` / `rr` / `slot`）です。alert() は全イベントが同じ webhook に飛ぶので、**bot 側は `event` を見て `zone_filtered` を必ず読み捨ててください**。

### チャート表示とイベントの対応

灰色のボックスは2系統あり、混同しやすいので破線の有無で区別します。

| 見た目 | 意味 | 対応イベント |
|---|---|---|
| 赤（sell）／アクア（buy）の実線ボックス | 有効なゾーン | `zone` |
| 枠が黄色に変わる | エントリー発火 | `entry` |
| **薄い灰色・実線**枠＋ラベルに `FILTERED` | フィルタ除外（発注対象外） | `zone_filtered` |
| **灰色・破線**枠（元は赤/アクア） | 失効したゾーン | `cancel` |

`alert()` はヒストリカル足では実行されないため、アラート作成時点より過去のボックスには対応する通知が存在しません。

`stale` フィールドはゾーン破棄水準の価格です。TradingView側のアラートが遅延・欠損してもbot単独で pending order を取り消せるよう、botでも同じ水準を監視することを推奨します。

## 5. v1 からの変更点（レビュー指摘への対応）

| # | 指摘 | 対応 |
|---|---|---|
| ① | 同種ピボット連続で極値が更新されない | `prev` をシフトせず、より高い高値／より安い安値で `curPrice/curBar` を上書き。`waveId` で波の同一性を追跡 |
| ② | 同一足で ph/pl が両方出た場合が未定義 | 直前ピボットと交互になる方を先に処理する2スロット方式 |
| ③ | base の再代入と retraceActive の非同期 | arm時に `sigHigh/sigLow/sigRange/sigDir/...` をスナップショット固定 |
| ④ | retrace の無効化条件がない | `full_retrace` / `timeout` / `lower_high`・`higher_low` の3種 |
| ⑤ | リペイント | arm・ブレイク・ゾーン管理をすべて `barstate.isconfirmed` 配下に |
| ⑥ | アラートにゾーンしか入っていない | entry / sl / tp / rr / 有効期限 / エントリー方式を Pine 側で確定 |
| ⑦ | 逆張り特有のリスク | 上位足EMAトレンド・ATR上限・セッション・最小RR・波の最小サイズ |
| ⑧ | 検証環境が未整備 | strategy版を別ファイルで用意（IS/OOS期間分割、リスク%サイジング付き） |
| ⑨ | `retraceDir=="long"` なのに `"sell"` を送る命名 | `waveDir`(up/down) と `tradeDir`(buy/sell) を完全分離。価格は `format.mintick` 精度で出力 |

### ④-3 の補足

「逆方向の新ピボット確定でキャンセル」を素直に実装すると、**押し目の安値ピボットで正常な待機まで全部消えてしまいます**（上昇波の押し目は、確定すれば必ず安値ピボットになるため）。そのため本実装では「baseHighを超えられない切り下げ高値が確定したとき」＝ブレイク失敗が構造的に確認できたときにだけ発火するようにしています。

## 6. 未対応・bot側で持つべきもの

- **スプレッド拡大時間帯の除外** — Pineから拡大幅が取れないため、除外セッション（既定 `2130-2300`）で近似するか、bot側で判定する
- **同時複数ゾーン** — 既定は同時1本（`zoneQueue=skip`）。複数保有するならbot側でキュー管理が必要
- **成績の確認** — strategy版は「作った」だけ。まず `htfMode=off / minRR=0` の素の状態でトレード数（母数）を確認するところから
